## Evidence and limits

The review used the captured PR metadata and local `upstream/pr/<number>` heads, including source diffs where the proposal's title or description did not match its full scope. A PR marked merged upstream may have equivalent code in this fork without its original merge commit; that is why disposition is stated separately from upstream status.

Focused checks cover native package identity/platform/rollback, extension activation and state, gallery asset metadata, cancellation compatibility, profile ownership, terminal transport, Markdown rendering, localization, builtin resource integrity and package-generation metadata. The worker bootstrap regression executes the generated bootstrap while substituting only its network-import boundary. The SSH integration fixture additionally exercises a real disposable OpenSSH server, binary SFTP, authentication, forwarding and PTY behavior. See [extension compatibility](EXTENSION_COMPATIBILITY.md), [packaging validation and limitations](PACKAGING.md) and [localization coverage](LOCALIZATION.md).

A passing fixture or Linux build is not proof of every extension or every operating system. Windows/macOS desktop behavior, the reporter's exact GPU/shell configuration, complete Nix/Flatpak installation and third-party Claude Code/Unity/Remote-SSH compatibility are not certified by this table. The native SSH workspace implementation does not implement Microsoft's remote extension-host protocol. No package-store listing or release publication is implied.

The metadata-cache proposals were declined for observable correctness risks, not because caching is categorically prohibited. A future cache needs mutation and watcher invalidation, external-change behavior and measurements before replacing fresh stat results. The broad Bun/restructure/agent rewrites were similarly reviewed without treating unrelated deletions or instruction files as necessary bug fixes.
